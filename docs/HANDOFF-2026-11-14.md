## 2. 使用者新決定（GDD v0.2）

### 預約關店（已確定）
- 玩家可事先設定時間，到時自動進入「準備關店」。
- 目的：上班日趕出門忘了關店，員工不會因此累垮。
- 假日可以不設，醒來後想多看一會兒營業畫面，再手動關店。
- 這是**玩家自己選的設定**，不是原本已否決的「系統強制關店」。
- 待定：平日和假日是否分別預設、預設開或關、頁面沒開著時如何離線結算（應以預約時間為準）。

### 防偷吃步（已確定方向）
使用者的核心目標是讓玩家**養成準時、規律的睡眠**，避免玩家「先按開店，再繼續滑手機」。

1. **員工疲勞＋備援**：疲勞會隨營業時間累積；低等級員工體力較低、較快耗盡，需要備援員工接替。這讓超長營業的收益有自然上限。
2. **開店後仍用手機**：額外獎勵任務失敗，並降低營業額（以「員工上班不專心」呈現）。
3. **營業時間不規律**：降低營業額。

## 3. Claude 提出、已記入文件的注意事項

- **網頁版偵測不到玩家用其他 App**，只知道遊戲頁面有沒有在前景。所以網頁版的第 2 條（開店後仍用手機）一律顯示「未驗證」，不給獎勵也不扣錢；要等 iOS 版確認可行後才啟用。iOS 的 Screen Time 相關 API 權限很嚴，需要實測。
- **平衡原則（建議，非已確定）**：初期員工＋備援要撐得過正常一晚睡眠（約 7～9 小時），不能懲罰睡飽的玩家；疲勞的負面效果應主要出現在明顯超時的營業。
- **離線營業**：整晚只用數字計算結果，早上打開時再把最後一段營業播成動畫。
- **測試快轉**是必備功能，不然每改一次都要等一整晚。

## 4. Claude 建議的技術簡化（尚未經使用者確認）
